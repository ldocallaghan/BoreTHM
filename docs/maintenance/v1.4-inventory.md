# v1.4 packaging inventory

Inventory date: 21 October 2026. Baseline: `v1.3.6`, commit `09967b13b3c391a92eb0ab92df7c2731aee8ed3a`.

This is the inventory checkpoint. No implementation or file moves have been made. Four earlier terminology corrections are present in `CHANGELOG.md`, `docs/maintenance/development.md`, `docs/science/breakout-timing.md` and `docs/science/design-comparisons.md`. They are separate from this inventory commit.

Core means the installed calculation library and built-in site definitions. Studies are internal evidence drivers that may require a checkout. Scripts produce figures or one-off analyses and have no importers in the repository's Python files.

### Supporting types and interface choices

The proposed public names do not include `wall_thermal.State` or `tool_thermal.Lump`, although two functions require objects with their attributes. `PipeType` requires layer objects with radii and a resistance method. General `WellGeometry` construction uses `StringSegment`, `HoleInterval` and `Survey`; `.single()` covers a simple well, but a pipe object is still needed. The named pipe constants and their factories are also outside the proposed public list.

Before documenting these as a stable, self-contained interface, confirm whether supporting types/factories should be public, or whether the argument attribute contracts and the internal construction imports are intentional. No additional exports or wrappers have been added at this checkpoint.

The circulation wrapper must honour an explicitly supplied `verbose` argument, including positional use. The current default is `True`; only the wrapper's implicit default changes. The breakout functions' opposite horizontal-stress orders need explicit documentation. No argument reordering is proposed.
