# v1.5.0: assess a site from an installed package

Release candidate prepared on 23 October 2026. Planned Git tag: `v1.5.0`.
Publication awaits the release checks and final review.

## New site workflow

An installed package can create, check and evaluate a TOML site file:

```sh
python -m pip install borethm==1.5.0
borethm-new-site mysite.toml
# edit mysite.toml
borethm-evaluate --site-file mysite.toml --check
borethm-evaluate --site-file mysite.toml --json mysite.json
```

Version 1.5.0 will be available from PyPI after publication. The
[new-site guide](../guides/new-site.md) explains the inputs and sources.
`--from KEY` starts from any built-in site. The public Python interface adds
`load_site` and `layered_geotherm`; the two export functions accept an optional
keyword-only `site_file` argument for the input path and checksum.

The opening result reading explains numerical validity, target scenarios,
whole-programme constraints and equipment checks. It is also exported as
`reading` in JSON. The [output guide](../guides/interpreting-results.md)
explains the status precedence and conditions.

The [documentation website](https://ldocallaghan.github.io/BoreTHM/) is built
from the maintained Markdown pages. Source and evidence links use the
release tag. Study reproduction commands write to a separate output folder.

## Changes to existing behaviour

### Required site selection

`borethm-evaluate` needs either `--site` or `--site-file`; its former Soultz
default is removed.

### TOML site template

`borethm-new-site` writes the packaged TOML template. The former
`examples/site_template.py` is removed. Python callers can still construct
a `SiteProfile` directly.

### Explicit coupling override

`evaluate(..., coupled=False)` switches coupling off even if the site's flag
is set. The default selection by calculation mode is unchanged. The
[API reference](../api.md#evaluate) describes the affected couplings.

### Cross-platform input checks

Site files preserve their supplied values exactly. Tests compare loaded
files with their stored records, and compare freshly generated files with
the Python definitions in the same environment. Formatting a fixed record
reproduces the committed UTF-8 bytes with LF line endings.

Comparisons between stored snapshots and independently recomputed inputs
use a shared relative round-off bound of `1e-12` for finite floating-point
values. This applies equally to every site and input unit, with no absolute
floor: a zero must remain zero. Structure, labels, booleans and integers
remain exact. These checks concern input snapshots; existing physical
regression tolerances are unchanged.

The fast compatibility matrix covers Python 3.11 to 3.14 on Linux, Windows
and macOS. Isolated wheel installations are checked on all three operating
systems. The full physical suite uses the locked Linux environment after
the compatibility, installation and documentation jobs pass.
