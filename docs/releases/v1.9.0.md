# v1.9.0: stated operating choices and the checks against their limits

Planned for release on 16 November 2026 as `v1.9.0`.

## What changed

The evaluator chooses the pipe, the flow, the tool and pump limits, the connection and trip timings, the run-in staging, the rate of penetration and the drilling and trip fluids by fixed rules. This release lets a user state any of these choices. A choice left unstated keeps its rule.

- **`Operations`.** `evaluate` takes `operations`, an `Operations` whose fields are all optional. `SiteProfile` has a new optional field of the same name, and a site file can give the same fields in an `[operations]` table. `validate_operations` checks the values, and `operation_defaults` gives each field's default value, unit, rule and source.
- **Result additions.** Results of the default calculation mode add `operations`, which records each choice as stated or default, the window profile and window widths, and checks of the pumps, the tool and the coating against their limits. No existing key or value changes.
- **Stated fluids.** A stated drilling or trip fluid heavier than water and inside its common window makes the status CONDITIONAL, with a condition that names the window it was checked against.
- **Public names.** 24 names are added to the package's public names, each documented on the [API page](../api.md). 15 are existing functions and classes, exported with their behaviour unchanged. The others are the four names of the operations interface, the wall model's grid as `WallGrid`, and four functions that give values that were module constants.

The [changelog](https://github.com/ldocallaghan/BoreTHM/blob/main/CHANGELOG.md) lists each addition. The [new-site guide](../guides/new-site.md#operating-choices) describes the fields, their ranges and their defaults, and [interpreting results](../guides/interpreting-results.md#operations-and-limit-checks) describes the result additions.

This is the interface the BoreTHM Workbench uses for its Programme and Design levers pages.

## Changes to results

None. The five built-in sites were evaluated under both physics choices at this release and at v1.8.0, and every value of the v1.8.0 `result_dict` apart from `versions`, 5,863 in all, was compared exactly: none changed and none is missing. The keys this release adds are listed under "What changed".

## Example

Newberry with a stated tool limit of 150 °C, below the default of 200 °C:

```python
from borethm import Operations, evaluate, find_site, result_dict

site = find_site("newberry")
ops = Operations(tool_limit_C=150.0,
                 sources={"tool_limit_C": ("assumed", "MWD tool rating")})
result = result_dict(evaluate(site, operations=ops))

print(result["status"]["label"])
limit = result["operations"]["tool_limit_C"]
print(limit["value"], limit["unit"], limit["stated"])
check = result["tool_check"]
for state in ("drilling", "connection", "run_in_staged", "run_in_unstaged"):
    c = check[state]
    print(f"{state:16} {c['peak_C']:6.1f} °C  margin {c['margin_C']:6.1f}  ok {c['ok']}")
```

```text
GO
150.0 C True
drilling           92.3 °C  margin   57.7  ok True
connection         92.4 °C  margin   57.6  ok True
run_in_staged      97.3 °C  margin   52.7  ok True
run_in_unstaged   175.7 °C  margin  -25.7  ok False
```

The operations record marks the tool limit as stated. Each check uses the stated limit, so the margins are measured from 150 °C. The unstaged run-in, with no circulation pauses, exceeds the limit, but it is reported for comparison and does not set the status: the status uses the staged run-in, which peaks at 97.3 °C. The status is GO, as it is with the default limit. This output came from the release candidate on Python 3.14.4 with the locked dependencies, in 80 seconds.

## Limitations

- **Stated values are used as given.** Where the evaluator would otherwise search for a value, stating it ends the search, and a check the stated value fails is reported as failed. The result does not check that a stated value is achievable with the rig or the tools, beyond the pump, tool and coating checks it reports.
- **A stated flow grid keeps its unit in every pass.** The evaluator reads its own grid as kg/s while the fluid is water and as L/s at surface once the fluid is weighted. A stated grid is in the unit it was given throughout.
- **Operations apply to the default calculation mode.** With `circulation` other than `'v1.3.4'`, or with `v10=True`, a stated value raises `ValueError`.

The [limitations page](../science/limitations.md#operating-choices-that-remain-fixed) lists the operating choices that remain fixed.
